# Планировыч для Android

Нативный Android-клиент существующего сервиса «Планировыч». Приложение написано на Kotlin и Jetpack Compose, не использует WebView и работает с тем же cookie-based API, что и веб-клиент.

## Требования

- Android Studio с JDK 17;
- Android SDK 36;
- minSdk 26, targetSdk 36, compileSdk 36;
- интернет для первой синхронизации Gradle.

## Открытие и запуск

1. В Android Studio выберите **Open** и укажите папку `android-app` (не корень npm-проекта).
2. Дождитесь Gradle Sync.
3. Выберите устройство или эмулятор с Android 8.0+ и нажмите **Run**.

Package id release-сборки: `ru.planirovych.app`. Версия: `0.1.0` (`versionCode 1`). Debug-вариант получает suffix `.debug`.

## Backend

Production URL задан единожды через `BuildConfig.API_BASE_URL` в `app/build.gradle.kts` и по умолчанию равен `https://planirovych.ru/`. Для локальной debug-сборки его можно заменить без правки исходников:

```bash
./gradlew assembleDebug -PAPI_BASE_URL=https://example.test/
```

URL обязан оканчиваться `/`. Секреты и API-ключи приложению не нужны. Серверные auth/device cookies сохраняются приложением между запусками.

## Сборка

```bash
./gradlew assembleDebug
./gradlew test
```

Debug APK появится в `app/build/outputs/apk/debug/app-debug.apk`.

Текущая версия включает нативное рабочее пространство, Timeline, задачи, привычки, заметки, чат ИИ, общие проекты и чаты, системные уведомления и виджет быстрых запросов.

### Gradle Wrapper в текстовом виде

Система ревью этого репозитория не принимает бинарные файлы в pull request. Поэтому официальный `gradle-wrapper.jar` хранится как текстовый `gradle-wrapper.jar.base64`. Скрипты `gradlew` и `gradlew.bat` автоматически восстанавливают игнорируемый JAR при первом запуске; вручную ничего создавать не требуется.

## Памятка безопасности перед возобновлением Android-разработки

Текущая папка Android — прототип. Этот раздел — требования для будущих PR, **не изменение приложения в рамках аудита безопасности сайта**:

- Не сохранять `btm_auth`, `btm_device`, пароли или другие токены в обычных `SharedPreferences`; использовать защищённое хранилище на базе Android Keystore (с продуманным поведением при сбросе ключей).
- Исключить сессионные cookie, токены, учётные данные и приватные данные пользователей из Auto Backup и device-to-device transfer. Пересмотреть `android:allowBackup` и настроить `dataExtractionRules` / `fullBackupContent` до выпуска.
- Использовать только HTTPS; не отключать проверку сертификата и hostname, не добавлять небезопасные исключения для release.
- Не встраивать `OPENAI_API_KEY`, `JWT_SECRET`, `TELEGRAM_BOT_TOKEN`, ключи ЮKassa или другие серверные секреты в APK, `BuildConfig`, ресурсы и логи.
- Вся авторизация и проверка принадлежности задач/заметок/вложений должны выполняться сервером. Изменённый в запросе ID не должен давать доступ к чужим данным.
- Обеспечить надёжный logout, очистку локальных данных при смене учётной записи и безопасное восстановление сессии без device fingerprint.
- Перед публикацией: отдельные unit/instrumentation security tests, аудит зависимостей Gradle, проверка release APK и тестирование входа/выхода при истечении токенов.

Пока Android не разрабатывается, эти требования не требуют новых переменных окружения и не влияют на web/Telegram.

## Системные уведомления Android

После первого запуска разрешите уведомления Планировычу в системном диалоге (Android 13+). Приложение получает сообщения из того же серверного `/api/system-notifications`, что используются на сайте и в Mini App. Уведомления доступны при работе приложения в фоне, а нажатие на сообщение задачи открывает задачу.

- Пока приложение открыто, новые события проверяются примерно раз в минуту.
- В фоне используется WorkManager: минимальная периодичность 15 минут. ОС может откладывать выполнение из-за энергосбережения, поэтому это **не мгновенный push**.
- На первом подключении старые события не показываются массово. Новые уведомления выводятся однократно. При смене учётной записи состояние сбрасывается.
- Для мгновенной доставки, когда приложение выгружено, потребуется отдельная серверная push-интеграция (например, FCM). Уведомления, которые не записываются в общую серверную ленту, этот клиент самостоятельно узнать не сможет.
- Плановые напоминания привычек и ИИ-чекапы теперь тоже зеркалируются в серверную ленту.

## Виджет быстрого запроса ИИ

Длительное нажатие на домашний экран Android → **Виджеты** → **Планировыч** → **Быстрый запрос ИИ**. Полоску можно растянуть по ширине.

- Касание текстового поля открывает быстрый ввод с клавиатурой. Редактируемые поля внутри самого стандартного App Widget не поддерживаются Android.
- Касание микрофона сразу открывает системное распознавание речи на русском языке (нужен установленный на устройстве речевой сервис). Распознанный текст можно исправить.
- Примеры: «Что важно сегодня?», «Мои просроченные задачи», «Составь план на завтра».
- Отправленные запросы появляются в общей серверной истории **«Быстрые запросы»**, которая синхронизируется с сайтом и Mini App. Отдельный чат для виджета не создаётся.

## Firebase Cloud Messaging (Android)

Firebase Messaging уже настроен для двух Android variants:
`app/src/debug/google-services.json` (`ru.planirovych.app.debug`) и
`app/src/release/google-services.json` (`ru.planirovych.app`).

- После успешной авторизации и получения FCM-токена Android автоматически
  регистрирует установку на сервере через `POST /api/system-notifications/android-devices`.
- Выход из учётной записи удаляет регистрацию через авторизованный DELETE,
  локальные обработанные ID и текущую идентичность, не удаляя чужие аккаунты.
- Сервер, а не Android, определяет время уведомления. Никакие локальные
  будильники для задач не создаются.
- Входящие сообщения исключительно **FCM data-only**. Показ и защита от
  дубликатов работают через общий persistent seen-ID, используемый и
  резервным WorkManager.
- Для работы FCM нужен **реальный Android-телефон с Google Play services**,
  включёнными уведомлениями и установленным новым APK. На устройствах без
  совместимых Google Play services этот канал может быть недоступен.
- Существующий опрос WorkManager остаётся резервом для пропущенных событий,
  а не основным транспортом.

Сервер на Timeweb должен содержать переменную `FIREBASE_SERVICE_ACCOUNT_JSON`
со **всем JSON закрытого серверного ключа**. Секрет нельзя помещать в Git
или APK. Серверная отправка использует короткоживущие OAuth-токены FCM HTTP v1.
При отсутствии переменной сервер продолжает работать без push, не падая.

### Проверка после слияния и деплоя

1. Убедиться, что миграция `20261026100000_android_push_outbox` выполнена,
   а в логах отсутствуют ошибки `[AndroidPush]`.
2. На Timeweb после обновления кода проверить переменную
   `FIREBASE_SERVICE_ACCOUNT_JSON` и перезапустить именно основной сервер.
3. Собрать и установить **новый** APK из актуальной ветки Android.
4. Открыть приложение, войти в аккаунт и разрешить уведомления. Это
   зарегистрирует FCM-токен на сервере.
5. Создать новое напоминание через сайт на 2–3 минуты вперёд,
   свернуть приложение, дождаться системного уведомления.
6. Проверить перенос дедлайна до наступления срока и убедиться, что
   пришло только одно уведомление по новой дате.
7. Проверить выход из аккаунта и вход в другой аккаунт без показа чужих push.

Основной серверный планировщик напоминаний по-прежнему может проверять
дедлайны примерно раз в минуту. FCM убирает 15-минутный интервал
фонового Android-опроса, но не гарантирует точность до секунды.
