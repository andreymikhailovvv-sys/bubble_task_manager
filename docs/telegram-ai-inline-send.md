# ИИ-инструмент: подготовить и отправить в Telegram

## Сценарий
В обычном, проектном, быстром ИИ-чате, в чате задачи и режиме концентрации,
веб-версии и Telegram Mini App:

«Сделай выжимку по тому, что мы обсуждали, и отправь Ване Иванову в Telegram».

1. Модель использует историю текущего ИИ-диалога или задачи; для сведений
   из личных заметок и задач общего чата она сначала вызывает уже
   существующие инструменты поиска и чтения.
2. Модель вызывает **prepare_telegram_send** с готовым текстом и именем.
   Этот инструмент только готовит предложение. Никаких MTProto send
   операций модель выполнять не может.
3. Сервер проверяет, что личный Telegram подключён и разрешён, загружает
   список реальных личных диалогов и ищет получателя **без выдуманных ID**.
   Точное/единственное совпадение подставляется сразу. При неоднозначном
   имени карточка требует ручного выбора.
4. Прямо внутри **сообщения ИИ** показывается блок Telegram, в стиле
   существующего окна быстрого отправления:
   - имя получателя (кликабельно: можно заменить, выбрать «Избранное»),
   - готовый текст с прокруткой,
   - **одна финальная кнопка «Отправить»**.
5. Только после клика на «Отправить» API передаёт сообщение в
   существующую durable очередь Telegram Quick Share. Существующие
   правила ограничения частоты, учёт статуса и audit сохраняются.
6. Карточка отображает статус задания. Повторный клик использует
   один и тот же UUID и не создаёт вторую отправку; после обновления
   страницы статус восстанавливается по сохранённому UUID.
7. Без подключённого Telegram модель сообщает о необходимости
   подключения, не рисует фиктивную карточку.

## Реализация
- Нет новых переменных окружения. Для чатов задачи имеется одна
  **nullable JSONB-колонка** `TaskAiMessage.telegramSendDraft`,
  миграция выполняется штатно при запуске сервера.
- Общий и проектные ИИ-чаты сохраняют `telegramSendDraft`
  в существующем JSON истории.
- В совместных задачах встроенная карточка доступна **только тому
  пользователю, который инициировал её создание**; другие участники
  могут видеть текстовое сообщение ИИ, но не приватный адресат и
  не операцию отправки.
- Контакты и Telegram ID не поступают на вход общей модели;
  модель знает только исходное имя, а серверное совпадение остаётся
  в структурированном ответе. ИИ не имеет tool для отправки.
- Поддерживаются только личные Telegram-диалоги и «Избранное»,
  без групп/каналов и автоматической синхронизации переписок.
- API `quick-send` по-прежнему требует сессию владельца,
  проверяет личный диалог, limits и idempotency, допускает только
  явно нажатую пользователем кнопку.
- Одна карточка на ИИ-запрос, без списков контактов в модели.

## Проверка после Merge
1. В общем ИИ-чате: «Напиши Ване Иванову, что завтра обсудим план, и
   отправь в Telegram»; проверить имя, текст, возможность изменения
   адресата, кнопку отправки.
2. В проектном чате: «Сделай выжимку нашего обсуждения и отправь
   Ивану Иванову»; ИИ должен использовать доступный контекст.
3. В задачном чате: «Составь краткий статус этой задачи и передай Ване».
4. С похожими именами: не выбирать автоматически случайного человека,
   показать возможность выбрать вручную.
5. Отправить тест в «Избранное», проверить сообщение в Telegram.
6. Перезагрузить страницу до и после отправки. Не должно быть
   второй отправки, карточка и статус должны остаться.
7. Проверить оба оформления (светлая/тёмная темы) и Mini App.
8. Проверить, что обычный ответ модели без просьбы отправить в Telegram
   не содержит карточки.
