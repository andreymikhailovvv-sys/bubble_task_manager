# Пользовательские интеграции Telegram

## Интерфейс
На главной странице слева от «О сервисе» расположена кнопка
«Интеграции». При наведении, фокусе или нажатии открывается
выпадающий список:
- **Telegram-бот**: статус по фактической привязке к Telegram-боту;
  раскрываемое описание и «Подключить» открывают существующий
  вход через Telegram, без нового способа авторизации;
- **Отправка в Telegram**: статус по действительной личной MTProto
  сессии, раскрываемое описание и «Подключить» открывают окно
  с инструкцией, полями `App api_id` и `App api_hash`,
  авторизацией через Telegram QR и поддержкой 2FA.
В обеих темах интерфейс отображает подключение, ошибки,
управление и отключение.

## Как пользователь подключается
1. Привязывает существующего Telegram-бота Планировыча.
2. Открывает https://my.telegram.org/apps. Лучше в режиме
   инкогнито: меньше проблем со старыми сессиями браузера.
3. Входит по номеру телефона, создаёт приложение в
   `API development tools` (если его ещё нет), копирует
   `App api_id` и `App api_hash`.
4. Вводит ключи в окне интеграции Планировыча. Сервер немедленно
   шифрует их и сохраняет только в зашифрованном виде;
   UI не сохраняет ключи в localStorage, не возвращает их обратно,
   не отправляет модели и очищает поля после сохранения.
5. QR-код: Telegram на телефоне → Настройки → Устройства →
   Подключить устройство, подтвердить вход. При запросе 2FA
   ввести пароль только в форме приложения.
6. После подтверждения проверяется совпадение Telegram ID
   с уже привязанным ботом. Только после проверки сервис
   сохраняет зашифрованную MTProto-сессию.
7. Отключение удаляет сессию и пользовательские ключи,
   пытается отозвать её в Telegram. Если Telegram не отвечает,
   пользователь получает указание вручную удалить сеанс в
   Telegram → Настройки → Устройства.

## Сервер
- Используем **имеющийся** `TELEGRAM_USER_SESSION_KEY`.
  Ключи пользователя шифруются отдельным AES-256-GCM ключом,
  полученным через HKDF, с owner-bound AAD.
- Удалены все admin pilot, remote-send, contact/history и
  тестовые QR endpoints и элементы из панели администратора.
  Авторизация теперь доступна владельцу через стандартную
  сессию Планировыча и same-origin POST.
- Внутреннее поле `pilotEnabled` используется как **признак
  явной настройки владельцем**, а не админская allowlist.
  Все прежние проверенные права, совпадение Telegram-бота,
  ограничения отправки, аудит, проверка контакта и закрытые
  флаги серверных функций продолжают действовать.
- Изменена только одна таблица для хранения зашифрованных
  ключей. Миграция **сбрасывает существующие старые пилотные
  подключения**, устанавливает pilotEnabled=false,
  удаляет старую зашифрованную сессию и отменяет ещё не
  отправленные фоновые пилотные задания. Привязку бота не меняет.
  Старые device sessions возможно потребуется удалить
  в самом Telegram через Настройки → Устройства.
- Сохранение ключей ограничено по частоте, запрещена их замена
  поверх активной сессии, QR-привязка привязана к конкретному
  зашифрованному credential snapshot. Хранилище user-specific,
  чужой userId с клиента не принимается.
- Новых переменных окружения нет. Старые серверные выключатели
  `TELEGRAM_USER_CLIENT_ENABLED`,
  `TELEGRAM_USER_READ_ENABLED`,
  `TELEGRAM_USER_SEND_ENABLED` остаются как есть. Если один из
  них был отключён, связанная функция остаётся отключённой.
- Миграция выполняется штатным `prisma migrate deploy`.
- Нет самостоятельного фонового мониторинга переписок.

## Smoke-check
1. После деплоя старый пилотный MTProto должен быть
   «Не подключено», даже если раньше была сессия.
2. При этом Telegram-бот остаётся «Подключено».
3. Открыть «Интеграции» на светлой и тёмной теме;
   описание разворачивается по нажатию, мобильное
   нажатие тоже работает.
4. Вставить правильные api_id/api_hash, получить QR,
   подтвердить через Telegram. Проверить статус «Подключено».
5. Отправить тестовое сообщение в «Избранное» из ИИ-чата,
   затем отправить обычному контакту через карточку ИИ.
6. Обновить страницу, проверить статус и возможность
   отправки без ввода ключей заново.
7. Отключить интеграцию, убедиться в статусе и отказе
   отправки до повторного подключения.
8. Убедиться, что старые админские тестовые панели и
   endpoints отсутствуют.
