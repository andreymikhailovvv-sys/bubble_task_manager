# Планировыч.Work · обзор и совместная работа (этап 5)

## UI
- Начальный экран больше не показывает промо-блоки, направления разработки и технические объявления.
- При входе автоматически выбирается первая **доступная** организация. Выбор вверху «Обзора» меняет контекст во всех вкладках без дополнительных просьб перейти к списку. Список разрешённых организаций приходит с существующего авторизованного endpoint. Прямой URL `/organizations/:id` по-прежнему работает.
- Выбор организации **не** открывает карточку; кнопка «Открыть карточку компании» делает это отдельно.
- Владелец, администратор и руководитель видят сводку компании, просрочки и проекты; сотрудник видит только доступные ему поручения, созданные им либо назначенные ему. Наблюдатель видит доступные ему записи без права оплаты ИИ/изменения.
- Справа внизу «Быстрые запросы» с компактным окном при наведении и полноэкранным режимом. В боковой колонке полного режима проекты строятся из реального списка организации, задачи выступают отдельными чатами. В каждом чате используется существующий `WorkAiPanel` и серверная история задачи.
- Компактные запросы пользователя и история диалогов изолированы по `OrganizationMember.id`. Сотрудник получает в ИИ-контекст только проекты и задачи, где участвует; владельцу для обычных быстрых запросов также выдаётся контекст доступных ему задач. Общий корпоративный диспетчер по-прежнему доступен руководству.
- Карточка фокуса корпоративной задачи открывается с «Обзора» и из списка проектов, содержит описание, дедлайн, приоритет, статус, создателя, исполнителя и живую панель «Помощь ИИ». Менеджер редактирует всё; участник-исполнитель/создатель меняет статус. Не происходит копирования личных Task.
- Форма общего чата и фокус имеют общую стилистику с личным Планировычем, но **не** подключают его персональные хранилища, вложения, автоматические действия, совместный чат через Telegram или всю функциональность личного окна фокуса. Их перенос требует отдельной tenant-aware адаптации и не должен работать через личную таблицу Task.

## Storage and access control
- Новые nullable `OrganizationProject.createdByMemberId`, `OrganizationWorkTask.createdByMemberId`, `OrganizationAiMessage.memberId`. Существующие записи сохраняются; старые задания без указания создателя останутся доступными по их исполнителю, менеджеру и участникам согласно текущим правам.
- Проект может иметь много корпоративных поручений. Новое поручение получает создателя и исполнителя как ссылки на **членство в этой же компании**. Нет дублирующих личных задач.
- Роль MEMBER просматривает проекты/поручения только если создала проект/поручение или назначена исполнителем. Её изменение ограничено статусом (сервер). Руководство имеет полный доступ внутри своей организации. Межорганизационный доступ ограничен через `organizationId`.
- Viewer не может делать AI-запросы, даже будучи назначенным исполнителем, и не видит кнопки платного чата.
- Хранилище corporate AI message имеет отдельный `memberId` для приватных быстрых диалогов; общие чаты компании и задачи остаются отдельными.
- Все корпоративные вызовы продолжают списывать организационные кредиты. Личная база Task, финансы User и личный AI chat не изменяются.
- В API `/dashboard` отдаётся максимум 200 задач и 100 проектов с `hasMoreTasks`. Для больших компаний понадобится пагинация.

## Deployment and smoke test
- Перед миграцией сделать backup Timeweb PostgreSQL, затем слить PR в `main`.
- Проверить два аккаунта (OWNER и MEMBER) и две организации: стартовый выбор, переключение, смена вкладок, назначение задачи, появление на панели сотрудника, открытие фокуса и общий ИИ. Убедиться, что запросы другого сотрудника нельзя прочитать.
- Отдельно проверить, что личный Планировыч и старые совместные задачи не изменились.
- B2B tenant-aware совместные задачи реализованы как одна корпоративная запись с двумя участниками. Это **не** автоматическое появление поручения в личном планировщике пользователя и не эквивалент старой персональной Collaboration-модели. Для полной функциональной эквивалентности нужно дальнейшее расширение.
