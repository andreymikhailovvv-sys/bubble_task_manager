# Планировыч Work: запуск закрытой корпоративной страницы

Текущий PR создаёт отдельный интерфейс Work в том же React/Express приложении. Он пока не создаёт организаций, не меняет задачи, базу данных, глобальную админку или Telegram Mini App.

## Как подготовить вход

1. Войдите в свой зарегистрированный аккаунт на https://planirovych.ru.
2. Откройте https://planirovych.ru/api/auth/me и скопируйте значение user.id (не токен и не пароль).
3. В переменных окружения сервиса Timeweb установите BUSINESS_ADMIN_USER_IDS со значением этого ID. Для нескольких администраторов IDs разделяются запятой.
4. После безопасного деплоя подключите work.planirovych.ru как дополнительный домен к существующему App Platform приложению с HTTPS. Основной домен не удалять.
5. Откройте work.planirovych.ru и войдите тем же логином и паролем.

Без BUSINESS_ADMIN_USER_IDS панель закрыта: после входа вернётся 503. С неразрешённым ID — 403. Без сессии — 401. Реальный администратор подтверждается через сервер и БД. Пароль ADMIN_PANEL_PASSWORD на эту страницу не действует.

Внимание: текущая auth-cookie привязана к хосту, поэтому вход на planirovych.ru не переносится автоматически на work.planirovych.ru. Войти на Work нужно отдельно. Существующая авторизация не изменяется.

## Маршруты и проверка

- На work.planirovych.ru загружается BusinessApp.
- В локальном Vite dev можно открыть localhost:5173/business-preview; в production основной домен по этому пути не показывает Work.
- GET /api/business/bootstrap — закрытый endpoint только для проверки входа, без корпоративных данных.
- На work-домене выдаётся X-Robots-Tag: noindex, nofollow.
- Не требуется новая БД, миграция, второй сервер или иной JWT_SECRET.

Перед merge: npm run build, npm run test --workspace client и npm run test --workspace server. Затем проверить, что личный сайт, мини-апп и остальные существующие API работают как прежде. На Work проверить 401/403/503/200, вход и выход. Разделы «Проекты», «Команда», «ИИ-диспетчер» и «Конфигурация» пока только визуальные заглушки.
