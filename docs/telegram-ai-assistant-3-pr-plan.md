# Telegram AI Assistant: архитектура в трёх PR

## Общий принцип

Новый пункт **«Интеграции → ИИ-ассистент Telegram»** использует текущую
owner-bound MTProto-сессию, верификацию Telegram ID, список личных диалогов,
групп и супергрупп, существующую систему уведомлений, кредитный кошелёк
и инструменты Планировыча. Никакого второго Telegram-аккаунта или
повторной реализации входа, истории и ручной отправки.

Выбор чата и одноразовое чтение последних сообщений в общем ИИ-чате
**не** равны разрешению на непрерывный мониторинг. Для каждого чата нужна
отдельная сохраняемая политика, а её активация всегда явная.

## PR1: настройка и права (этот PR)

- Отдельная карточка ассистента в домашнем меню «Интеграции».
- Выбор конкретного DM, группы или супергруппы из списка *собственного*
  MTProto-аккаунта. Сервер повторно верифицирует peer при сохранении.
- Четыре дискретных бегунка: режим переписки `OBSERVE / SUGGEST / AUTO`,
  режим создания задач `NONE / SUGGEST / AUTO`, частота проверки
  `5 / 30 / 180` минут, дневной лимит `50 / 100 / 250 / 500 /
  1000 / 2500 / 5000 / без ограничения` кредитов.
- «Без ограничения» передаётся как `dailyCreditLimitMilli=null`:
  не отменяет проверку общего кредитного кошелька, а лишь убирает
  индивидуальный дневной потолок переписки.
- Поле инструкций и один чекбокс: уведомления о важных событиях и рисках.
  Разделение дневного/месячного лимита и лишние настройки убраны.
  PR1 только сохраняет значения: применять их начнёт PR2.
- Сохраняемые `AUTO`-режимы не запускают ни отправку сообщений, ни
  изменение задач. Для обеих функций потребуется отдельное разрешение.
- Ограничение 25 профилей на владельца и безопасные пределы значений.
- Пока нет активатора и рабочего процесса: `isEnabled=false` для каждого
  нового и обновлённого профиля. Нет фоновых чтений, вызовов LLM или отправок.
- При ручном отключении Telegram все профили удаляются транзакционно вместе
  с отзывом локальной сессии. Удаление собственного профиля возможно даже
  при недоступной сессии.
- Новых переменных окружения нет, нет изменений старых API чата с ИИ.

## PR2: мониторинг, сводки и контроль расходов

- Добавить **явное разрешение включить мониторинг**, только для
  выбранного профиля. Дефолт после миграции/переподключения: выключено.
- Реализовать распределённый воркер через существующую PostgreSQL базу:
  аренда задач с TTL, atomic claim, устойчивое восстановление после
  рестарта/нескольких экземпляров приложения. Не держать постоянные
  MTProto-клиенты для каждого профиля; ограничить параллелизм,
  проверять состояние подключения и разрешения перед каждым чтением.
- Первый запуск запоминает текущую границу, **не** пересылает ИИ всю
  старую историю без дополнительного согласия.
- Обрабатывать только новые сообщения относительно безопасного checkpoint,
  учитывать удалённые/пропущенные пакеты, не отправлять в модель сообщения
  из невыбранных чатов. Защита от двойной обработки на уровне БД.
  Для групп отдельно определять участников, не скачивать вложения.
- Экономить вызовы: объединять несколько сообщений, сначала дешёвая
  детерминированная фильтрация, затем ограниченный LLM-анализ.
  Нулевой бюджет, отсутствие новых сообщений и пауза не вызывают LLM.
- Резервировать и списывать кредиты через **существующий** кошелёк
  с транзакционным соблюдением выбранного дневного лимита (если не null),
  остатка общего кошелька и защиты от дублей. Видимый счётчик
  «израсходовано сегодня / предел». При достижении заданного порога
  автоматическая пауза и одно уведомление; при null нет локального
  дневного лимита, но остаток общего кошелька обязателен.
- Вывод: карточка важных событий, принятых решений, договорённостей,
  открытых вопросов, обязательств, сроков, запросов клиента и рисков,
  сводки по запросу и автоматические агрегированные сводки
  (по выбранному ассистентом расписанию, в часовом поясе владельца).
  Связь с существующими уведомлениями и **предложением** создать задачу;
  без автоматического изменения рабочих задач.
- Отдельный запрос текущего статуса, последней проверки, ошибки,
  последней сводки; явные включение/пауза/отключение. Редактирование
  прав немедленно инвалидирует текущие задания.
- Хранить только минимальные структурированные результаты и метаданные.
  Не сохранять тексты всей переписки в логах и аналитике.

## PR3: безопасные черновики и автоматизация коммуникаций

- `SUGGEST`: готовый ответ по контексту, пользователю показываются
  получатель, текст, источник договорённости, кнопка редактировать,
  одноразовое явное подтверждение отправки.
- `AUTO`: отдельное явное включение и подтверждение правил на каждый
  чат **после** релиза PR3. Выбор AUTO в PR1 ничего не активирует.
- Разрешённые случаи по умолчанию: простые ответы по известному контексту,
  подтверждение получения, запрос уточнения. Остальное в черновик.
  Деньги, скидки, новые сроки/обязательства, юридические вопросы,
  конфиденциальные данные, вложения и неоднозначные адресаты безусловно
  требуют подтверждения человека.
- Ограничения скорости, число ответов в день, ограничения по времени,
  пауза/kill switch и защита от ответов на собственные исходящие сообщения,
  ботов, циклов и повторной отправки. Проверить актуальные условия
  и владельца непосредственно перед отправкой.
- Durable outbox с idempotency key; из состояния «отправка начата»
  не повторять запрос автоматически при неизвестном результате.
  Отображать журнал действий без текстов личной переписки в техлогах.
- Групповые автоответы отдельно разрешать; безопасный дефолт: выключено.
- Режим `taskMode=NONE` отключает предложения и создание задач,
  `SUGGEST` создаёт только предложения с подтверждением,
  `AUTO` требует отдельного явного включения и строгих правил на PR3.
  Автоматическое создание задач не должно открывать неограниченный
  доступ к редактированию/удалению других задач.

## Проверка PR1 после деплоя

1. Применить стандартный `prisma migrate deploy`, убедиться, что сайт
   загружается, личный Telegram и существующие ИИ-чаты работают как раньше.
2. Открыть меню «Интеграции» и новый пункт на светлой и тёмной теме.
3. Открыть настройки без Telegram: список недоступен, сохранённые
   профили можно удалить, нельзя включить мониторинг.
4. С подключённым Telegram выбрать личный чат, группу и супергруппу,
   сохранить разные режимы, интервалы и бюджеты.
5. Перезагрузить страницу: настройки сохраняются, каждый профиль
   помечен «Не запущено». Нет фоновых списаний кредитов.
6. Проверить три положения каждого из первых трёх бегунков,
   все восемь положений бюджета включая «Без ограничения»,
   восстановление после перезагрузки, неверный chatId и слишком
   длинные инструкции.
7. Удалить профиль, убедиться, что список обновляется.
8. Отключить Telegram и подключить снова: старые политики удалены.
9. Проверить, что чтение по разовому согласию и ручная отправка
   по-прежнему работают и НЕ включаются от сохранения политики.
